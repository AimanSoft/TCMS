# حالات الاستخدام الرئيسية (Use Cases)

## 1. مدير السفر (Travel Manager)

### UC-001: إنشاء طلب سفر جديد
- **المُعني**: الموظف
- **الهدف**: إنشاء طلب سفر جديد مع تفاصيل الرحلة والميزانية
- **المسار**: Client → API Gateway → Request Service → PostgreSQL
- **الأحداث**: `RequestSubmittedEvent`
- **النتائج**: يتم حفظ الطلب وبدء سير الموافقات

### UC-002: مراجعة واعتماد/رفض الطلبات
- **المُعني**: المدير المباشر
- **الهدف**: مراجعة طلبات الموظفين والموافقة عليها أو رفضها
- **المسار**: Client → API Gateway → Approval Service → PostgreSQL
- **الأحداث**: `ApprovalGrantedEvent` أو `RequestRejectedEvent`
- **النتائج**: تحديث حالة الطلب وإشعار الموظف

### UC-003: إدارة الميزانية
- **المُعني**: مدير المالية
- **الهدف**: مراقبة وتحليل الميزانية الإجمالية للسفر
- **المسار**: Dashboard → Report Service → PostgreSQL
- **النتائج**: تقارير مالية مع تفاصيل المصروفات

## 2. الموظف (Employee)

### UC-004: تقديم طلب سفر
- **المُعني**: الموظف
- **الهدف**: تقديم طلب سفر مع تفاصيل كاملة
- **المسار**: Client → API Gateway → Request Service → PostgreSQL
- **الأحداث**: `RequestSubmittedEvent`
- **النتائج**: إنشاء الطلب وإرساله للموافقة

### UC-005: متابعة حالة الطلب
- **المُعني**: الموظف
- **الهدف**: التحقق من حالة طلب السفر الخاص به
- **المسار**: Client → API Gateway → Request Service → PostgreSQL
- **النتائج**: عرض الحالة الحالية مع التفاصيل

### UC-006: رفع المستندات المطلوبة
- **المُعني**: الموظف
- **الهدف**: رفع فواتير وإيصالات السفر
- **المسار**: Client → API Gateway → File Service → MongoDB
- **النتائج**: تخزين المستندات وربطها بالطلب

## 3. النظام (System)

### UC-007: معالجة الدفعات تلقائياً
- **المُعني**: النظام
- **الهدف**: معالجة مدفوعات السفر تلقائياً بعد الموافقة
- **المسار**: Payment Service → Payment Gateway → RabbitMQ
- **الأحداث**: `PaymentCompletedEvent`
- **النتائج**: تحديث الحالة المالية وإخطار الأطراف المعنية

### UC-008: إنشاء تقارير دورية
- **المُعني**: النظام
- **الهدف**: إنشاء تقارير يومية/أسبوعية/شهرية تلقائياً
- **المسار**: Report Service → PostgreSQL → File Storage
- **النتائج**: تقارير PDF/Excel تُرسل عبر البريد الإلكتروني

### UC-009: إرسال إشعارات فورية
- **المُعني**: النظام
- **الهدف**: إرسال إشعارات فورية للأحداث المهمة
- **المسار**: Notification Service → RabbitMQ → Email/SMS/Push
- **الأحداث**: أحداث النظام المختلفة
- **النتائج**: وصول الإشعارات في الوقت المناسب

## 4. المسؤول (Admin)

### UC-010: إدارة المستخدمين والصلاحيات
- **المُعني**: المسؤول النظام
- **الهدف**: إدارة الحسابات والصلاحيات والرواتب
- **المسار**: Client → API Gateway → User Service → PostgreSQL
- **النتائج**: تحديث البيانات الشخصية والصلاحيات

### UC-011: مراقبة النظام
- **المُعني**: المسؤول النظام
- **الهدف**: مراقبة أداء النظام وصحة الخدمات
- **المسار**: Dashboard → Monitoring Service → Prometheus/Grafana
- **النتائج**: لوحات معلومات حية وتنبيهات

### UC-012: إدارة التكوينات
- **المُعني**: المسؤول النظام
- **الهدف**: تعديل إعدادات النظام وقواعد الأعمال
- **المسار**: Admin Panel → Config Service → Database
- **النتائج**: تطبيق التغييرات دون إعادة التشغيل
