# مخطط تدفق البيانات (Data Flow)

## نظرة عامة

يصف هذا المستند كيف تتدفق البيانات عبر نظام TCMS من نقطة الإدخال إلى التخزين والمعالجة.

## تدفق البيانات الرئيسي

### 1. تدفق طلب السفر

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  Client   │───▶│  API Gateway │───▶│ Request      │───▶│  PostgreSQL  │
│           │    │              │    │ Service      │    │              │
└──────────┘    └──────────────┘    └──────┬───────┘    └──────────────┘
                                           │
                                           │ Event
                                           ▼
                                    ┌──────────────┐
                                    │   RabbitMQ   │
                                    │              │
                                    │  Event Bus   │
                                    └──────┬───────┘
                                           │
                    ┌──────────────────────┼──────────────────────┐
                    │                      │                      │
                    ▼                      ▼                      ▼
            ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
            │ Approval     │    │ Notification │    │   Report     │
            │ Service      │    │ Service      │    │   Service    │
            └──────────────┘    └──────────────┘    └──────────────┘
```

## مصادر البيانات

### PostgreSQL
- بيانات المستخدمين
- بيانات الطلبات
- بيانات الموافقات
- السجلات التاريخية

### MongoDB
- المستندات المرفوعة
- البيانات غير المنظمة
- سجلات الأحداث

### Redis (Cache)
- جلسات المستخدمين
- البيانات المتكررة الطلب
- نتائج التصفية

## تنسيقات البيانات


## أمان البيانات

- تشفير SSL/TLS لجميع الاتصالات
- تشفير البيانات الحساسة في قاعدة البيانات
- JWT للمصادقة والتفويض
- Rate limiting على API Gateway
- مراقبة وتسجيل جميع عمليات البيانات

## نسخ البيانات والتزامن

- استخدام Change Data Capture (CDC) للمزامنة
- النسخ الاحتياطي اليومي لقواعد البيانات
- استعادة الكوارث مع نسخ احتياطية جغرافية
