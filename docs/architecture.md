# بنية نظام TCMS المعمارية

## نظرة عامة

يستخدم نظام TCMS بنية هجينة تجمع بين **Microservices** و **API Gateway** و **Event-Driven Architecture** لتحقيق أقصى أداء وقابلية للتوسع.

## المكونات الرئيسية

### 1. API Gateway
- **المسؤولية**: نقطة دخول واحدة لجميع العملاء
- **المهام**:
  - توجيه الطلبات للخدمات المناسبة
  - المصادقة والتفويض
  - تحديد معدل الطلبات (Rate Limiting)
  - تحويل البروتوكولات
- **التقنية**: NestJS + @nestjs/microservices

### 2. Microservices
#### خدمة المستخدمين (User Service)
- إدارة المستخدمين والمصادقة
- إدارة الأدوار والصلاحيات

#### خدمة الطلبات (Request Service)
- إنشاء وإدارة طلبات السفر
- تتبع الحالة

#### خدمة الموافقات (Approval Service)
- سير عمل الموافقات
- الإشعارات

#### خدمة الدفع (Payment Service)
- معالجة المدفوعات
- التكامل مع بوابات الدفع

#### خدمة التقارير (Report Service)
- إنشاء التقارير
- التحليلات

### 3. Event-Driven Architecture
- **الوسيط**: RabbitMQ
- **الأحداث الرئيسية**:
  - `PaymentCompletedEvent`
  - `RequestSubmittedEvent`
  - `ApprovalGrantedEvent`
  - `RequestRejectedEvent`

## تدفق البيانات

1. العميل يرسل طلباً عبر API Gateway
2. API Gateway يوجه الطلب للخدمة المناسبة
3. الخدمة تعالج الطلب وتنشر حدثاً على RabbitMQ
4. الخدمات الأخرى تستمع للأحداث وتستجيب
5. النتائج تُعاد للعميل عبر API Gateway

## أنماط التصميم المستخدمة

- **CQRS**: فصل مسارات القراءة والكتابة
- **Saga Pattern**: إدارة المعاملات الموزعة
- **Circuit Breaker**: حماية الخدمات من الأعطال
- **Event Sourcing**: تتبع تغييرات الحالة عبر الأحداث
